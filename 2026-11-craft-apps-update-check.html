Craft apps: disabling the update check

#linux #arch-linux #rust

This article describes how the startup update check of the 13 Craft desktop apps I use is disabled. On my test system, the apps are installed from the Arch repositories, while upstream publishes several releases per day and provides an auto-updater. Therefore, every launch opened an "update available" prompt for me. The apps provide no setting for the check. The switch is a JSON file owned by the launcher.

Scope

The behavior was verified against the releases of November 11, 2026 (v0.18.1 to v0.24.1) and against craft-libs master of November 15, 2026.

Procedure

  1. Create the directory and open the versions file (Listing 1). The path is $XDG_DATA_HOME/ArtCraft/versions/versions.json, by default ~/.local/share/ArtCraft/versions/versions.json. CRAFT_VERSIONS_FILE=/absolute/path overrides it.
  2. Add one entry per app (Listing 2). Any entry other than "Stable" disables the check.
  3. Validate the file with jq . ~/.local/share/ArtCraft/versions/versions.json. Invalid JSON is read as an empty file, and every app follows stable again.
  4. For PhotoCraft, turn off Preferences › General › Automatically Check for Updates in addition, or set the preference in ~/.config/photocraft/prefs.json (Listing 3).

The pinned string is opaque to the apps, as only the launcher interprets it. "Nightly" has the same effect, as does an entry the app cannot parse.

The preference is read once at startup. Help › Check for Updates keeps working.

Verification

  • With the file in place, each app logs one INFO line per start: follows the launcher's choice (...); no update offered here.
  • The manual check under Help › Check for Updates answers "up to date".

Mechanism

All Craft desktop apps share one crate, craft-update in storytold/craft-libs. It drives the startup check and Help › Check for Updates.

  1. On the first frame, the app calls Updater::check_at_start.
  2. Before any network request, the app reads the launcher's version file (crates/update/src/pins.rs).
  3. An entry other than "Stable" marks the app as managed by the launcher. The check ends with "nothing newer": no request is sent to GitHub and no prompt is shown.
  4. Only the launcher writes the file. The apps read it, and pacman never sees it.

PhotoCraft runs its update check inside its engine (help.checkForUpdates), not only through the shared updater. The versions file suppresses the dialog but not the request. The preference suppresses both.

Limitations

  • The twelve other apps provide no preference, no flag, and no environment variable for the check. The file is the only switch.
  • EffectCraft skips the check only under --control, its automation mode.
